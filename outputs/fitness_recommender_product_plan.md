# 健身进阶推荐器产品方案 v0.1

> 面向已有训练基础用户的个性化健身进阶推荐产品方案
> 
> 当前前提：**训记已确认支持通过 API Key 导出训练数据**

---

## 1. 产品定义

### 1.1 产品名称（暂定）
- 健身进阶推荐器
- 英文可暂定：**Progressive Fitness Planner**

### 1.2 产品一句话定义
一个面向有一定训练经验用户的智能训练决策助手，基于身体状态、训练目标、饮食规律和近期训练记录，自动分析用户当前状态，并生成**下一次更科学的训练计划与进阶建议**。

### 1.3 核心价值
和一般训练记录产品不同，本产品的重点不是“帮用户记训练”，而是：

1. **判断用户当前训练状态**
   - 是否适合继续加重量
   - 是否处在疲劳积累或平台期
   - 减脂期是否出现恢复不足
   - 当前训练量是否合理

2. **给出下一次训练的具体建议**
   - 哪些动作该加重
   - 哪些动作该维持
   - 哪些动作该减量或减少组数
   - 应做多少组、多少次、以什么强度完成

3. **结合目标动态调整计划**
   - 增肌
   - 减脂保肌
   - 力量提升
   - 局部部位强化

4. **自动接入训记数据，减少手动记录负担**
   - 直接同步训练记录
   - 自动分析近 2-6 周训练表现
   - 持续更新建议

---

## 2. 产品目标

### 2.1 用户目标
帮助用户解决以下问题：
- 我现在训练状态到底如何？
- 我下次某个动作该不该加重量？
- 我最近为什么卡住了？
- 减脂时怎么尽量保住力量和肌肉？
- 想强化某个部位，训练该怎么调？

### 2.2 商业/产品目标
第一阶段先验证以下核心命题：

> 用户是否愿意为了“更科学、可解释、能持续跟踪的训练进阶建议”持续使用产品。

### 2.3 MVP 阶段成功标准
若上线 MVP，建议以以下指标判断是否有效：
- 用户能在 5 分钟内完成初始化
- 成功导入训记训练数据的用户比例 > 70%
- 至少 50% 用户愿意查看并使用“下次训练建议”
- 至少 30% 活跃用户连续 2 周以上查看推荐
- 用户主观反馈中，认为“建议有帮助/有参考价值”的比例 > 60%

## 3. 目标用户

### 3.1 核心用户画像
**已有一定训练经验的力量/增肌/减脂用户**，典型特征：
- 训练经验 6 个月以上
- 每周训练 3-6 次
- 熟悉动作、组数、次数、重量的概念
- 能理解基础训练安排
- 已开始遇到进阶问题，而不是“怎么入门”问题

### 3.2 典型用户场景

#### 用户画像 A：稳定增肌型
- 训练 1-2 年
- 每周 5 练
- 想提高卧推、深蹲、围度
- 困惑点：不知道什么时候该加重量，怕乱加影响动作质量

#### 用户画像 B：减脂保肌型
- 有训练习惯，正在热量缺口期
- 困惑点：减脂时力量下降是否正常，训练量如何调，如何避免掉太多肌肉

#### 用户画像 C：平台期突破型
- 某些动作 1-2 个月进步缓慢
- 困惑点：是否该换进阶策略，还是只是恢复不够

### 3.3 MVP 不优先覆盖人群
- 完全零基础新手
- 有复杂伤病史，需要医疗级建议的用户
- 只做低频轻运动记录、不重视训练质量的泛用户

---

## 4. 产品定位与边界

### 4.1 产品定位
这是一个：
- **训练分析与决策产品**，不是单纯记录工具
- **个性化推荐产品**，不是固定模板课表库
- **偏中高级训练用户工具**，不是新手教学产品

### 4.2 明确不做的事情（至少在 MVP 阶段）
- 不替代医生/康复师判断伤病
- 不做高度复杂的营养处方系统
- 不先做社交社区
- 不先做完整视频教学体系
- 不先做 AI 聊天陪练主入口

### 4.3 推荐原则
- 输出的是**科学建议**，不是绝对命令
- 建议必须尽量**可解释**
- 优先保证**安全性、渐进性、连续性**

---

## 5. 核心使用流程

### 5.1 用户主流程
1. 注册/登录
2. 完成基础档案填写
3. 绑定训记 API Key
4. 导入最近训练记录
5. 系统分析当前训练状态
6. 用户查看“下次训练建议”
7. 用户训练完成后，新数据同步
8. 系统更新下一次建议

### 5.2 首次使用流程
首次使用需完成：
- 身体信息输入
- 训练目标选择
- 训练分化输入
- 当前饮食阶段输入
- 恢复情况基础问卷
- 训记 API 数据连接
- 最近 2-6 周训练记录解析

### 5.3 每日/每次训练前流程
用户进入产品后，可直接看到：
- 今日推荐训练日
- 本次动作建议
- 每个动作建议重量/组数/次数
- 是否建议加重/维持/减量
- 简短原因说明

## 6. 核心功能设计

## 6.1 模块 A：用户档案与目标设置

### 功能目标
建立推荐引擎所需的基础上下文。

### 输入字段

#### 基础身体信息
- 性别
- 年龄
- 身高
- 体重
- 体脂率（可选）
- 围度数据（可选）

#### 训练信息
- 训练年限
- 每周训练频率
- 当前训练分化
  - 推拉腿
  - 上下肢
  - 全身
  - 五分化
  - 自定义
- 常练动作 / 主项动作

#### 训练目标
- 增肌优先
- 减脂优先
- 力量提升优先
- 维持体型
- 局部强化（肩/胸/背/腿/手臂等）

#### 恢复情况
- 平均睡眠时长
- 工作/生活压力
- 日常活动量
- 是否存在疼痛或旧伤

#### 饮食状态
- 当前阶段：增肌 / 维持 / 减脂
- 是否规律记录热量
- 是否基本满足蛋白质摄入
- 饮食执行稳定度（高/中/低）

---

## 6.2 模块 B：训记数据接入

### 功能目标
自动获取用户训练历史，作为推荐引擎输入。

### 数据接入方式
- 用户输入训记 API Key
- 用户授权后触发数据同步
- 支持首次全量同步 + 后续增量同步

### 首期同步范围建议
优先读取以下数据：
- 训练日期
- 训练计划名称 / 训练日类型
- 动作名称
- 组数
- 每组重量
- 每组次数
- 每组记录时间（如有）
- RPE / 备注（如有）
- 完成状态（如有）

### 数据处理要求
- 统一动作命名
- 去重与异常值识别
- 将动作归类到肌群/动作模式
- 将历史训练映射到周、训练日、动作趋势维度

### 与训记接口相关的产品要求
- 支持手动重新同步
- 支持查看最近同步时间
- 支持 API Key 失效提醒
- 支持同步失败错误提示

---

## 6.3 模块 C：训练状态分析

### 功能目标
将原始训练记录转成用户可理解的状态判断。

### 分析维度

#### 1）动作进展状态
- 是否连续完成目标次数
- 是否达到进阶条件
- 是否连续失败
- 相同重量下表现是否提升

#### 2）训练负荷状态
- 单动作训练量趋势
- 单肌群周训练量
- 总体训练频率变化
- 最近 1-2 周是否训练压力偏高

#### 3）恢复状态
结合以下信号进行判断：
- 表现是否下滑
- RPE 是否上升
- 睡眠/压力输入是否恶化
- 是否出现连续高疲劳训练

#### 4）目标匹配状态
- 当前训练结构是否符合增肌目标
- 当前安排是否适合减脂保肌
- 局部强化肌群训练量是否足够

### 输出结果示例
- 当前总体状态：可正常推进
- 背部训练量偏低
- 下肢疲劳偏高
- 卧推可尝试加重
- 深蹲暂不建议冲重量

---

## 6.4 模块 D：下次训练推荐

### 功能目标
生成用户最关心的具体建议。

### 推荐输出层级

#### 层级 1：本次训练结论
- 今天适合正常推进 / 保守推进 / 恢复性训练

#### 层级 2：动作级建议
每个动作输出：
- 建议重量
- 建议组数
- 建议次数范围
- 建议强度（如保留 1-2 次余力）
- 建议状态：加重 / 维持 / 减量 / 替换动作

#### 层级 3：解释说明
为关键动作提供简单解释：
- “卧推已连续两次完成目标次数，建议加重 2.5kg”
- “深蹲上次后两组明显掉次，建议维持重量再巩固一次”
- “减脂期恢复压力较高，建议辅助动作减少 1 组”

---

## 6.5 模块 E：周期建议

### 功能目标
不只给下次训练建议，也提供短周期方向。

### 输出内容
- 本周训练推进建议
- 未来 2-4 周训练倾向
- 是否接近减量周
- 若持续卡住，建议切换哪种进阶策略

### 示例
- 卧推未来两周继续双进阶
- 下肢训练第 4 周建议安排减量周
- 当前减脂期建议优先维持主项强度，辅助动作总量下降 10%-20%

---

## 6.6 模块 F：饮食与恢复提醒

### 功能目标
给出影响训练结果的必要提醒，但不把系统做成完整营养 App。

### 输出内容
- 当前体重变化是否过快
- 恢复状态是否影响进阶
- 蛋白质摄入是否可能不足
- 睡眠不足时是否应保守推进

### 边界
- 不直接给复杂食谱
- 只做和训练建议强相关的提醒

---

## 7. 推荐引擎设计（MVP 版）

MVP 阶段建议先采用**规则引擎 + 阈值判断 + 可解释建议**，而不是一开始就用黑盒 AI。

## 7.1 状态判断框架
先把用户状态分为以下几类：
- A. 可正常进阶
- B. 可保守进阶
- C. 暂时维持
- D. 疲劳偏高，建议减量
- E. 平台期，建议切换策略
- F. 减脂保护模式

---

## 7.2 核心动作进阶逻辑

### 适合加重的条件（示例）
满足多数条件时建议加重：
- 最近 1-2 次训练均完成目标次数
- 主观强度可控
- 动作表现稳定
- 恢复状态正常

### 适合维持的条件（示例）
- 目标次数未完全达标
- 虽完成但后几组明显掉次
- 同重量仍不稳定

### 适合减量的条件（示例）
- 连续失败
- 疲劳高且恢复差
- 动作质量明显下降
- 减脂期状态明显下滑

### 建议的最小进阶单位
- 上肢：1.25kg / 2.5kg
- 下肢：2.5kg / 5kg

---

## 7.3 进阶策略支持
MVP 至少支持以下几种：

### 1）固定目标次数达标后加重
示例：3×5 完成后，下次加重

### 2）次数区间进阶
示例：8-10 次区间，当所有组都达到上限后再加重

### 3）双进阶
先补足次数，再提升重量

这是最适合 MVP 的三种方式，简单、实用、解释性强。

---

## 7.4 疲劳判断逻辑
判断依据可包括：
- 同重量表现下降
- RPE 升高
- 睡眠差 / 压力高
- 连续多次接近力竭
- 同肌群周训练量偏高

### 疲劳状态建议
- 轻疲劳：维持主项重量，辅助减量
- 中疲劳：减少 10%-20% 总量
- 高疲劳：建议恢复周或替换为轻量训练

---

## 7.5 不同目标模式下的推荐策略

### 增肌模式
- 优先保障训练量逐步增长
- 主项和辅助项共同推进
- 强调薄弱肌群补量

### 减脂模式
- 优先维持主项强度
- 适度降低总量
- 避免频繁追求所有动作同时进步
- 更强调恢复与饮食执行提醒

### 力量提升模式
- 主项优先
- 更强调强度推进
- 辅助动作围绕主项短板服务

### 局部强化模式
- 重点部位增加频率或训练量
- 在不过度影响恢复的前提下做偏置分配

## 11. 关键产品规则

### 11.1 推荐必须可解释
每条关键推荐都要带“为什么”。

### 11.2 推荐强度要保守
特别是首次接入时，不应激进加重。

### 11.3 对异常情况优先保守处理
如出现：
- 疼痛反馈
- 明显恢复差
- 连续表现下滑
- API 数据缺失
则优先给出维持/减量建议。

### 11.4 数据不足时明确提示
例如：
- “近两周数据不足，以下建议仅供参考”
- “未检测到足够的卧推历史记录，暂不建议自动加重”

## 12. 技术与实现建议（产品层）

### 12.1 推荐系统架构建议
MVP 采用：
- 数据同步模块
- 数据清洗与动作映射模块
- 规则判断引擎
- 推荐生成模块
- 解释生成模块

### 12.2 为什么不建议一开始就做纯 AI 决策
原因：
- 可解释性不足
- 推荐难以校验
- 训练安全边界不好控制
- MVP 阶段更需要稳定可用，而不是复杂炫技

### 12.3 后续可迭代方向
- 引入更智能的个性化参数学习
- 引入用户反馈回路（本次建议是否有用）
- 用历史表现校准用户进阶速度

---

## 13. 风险与难点

### 13.1 训记接口层面
- API 字段是否稳定
- 动作命名是否标准化
- 是否能增量同步
- 是否存在历史数据缺失

### 13.2 推荐准确性层面
- 用户饮食/恢复数据可能不完整
- 用户动作质量系统无法直接感知
- 同样的训练表现不一定代表同样的恢复状态

### 13.3 用户体验层面
- 首次设置不要过长
- 推荐结果不能太复杂
- 不要让用户感觉“被系统控制”，而应感觉“被专业辅助”

---

## 14. 产品差异化主张

建议主打以下定位：

### 面向用户的表达
- 不只是记录训练，而是告诉你下一次该怎么练
- 不只是通用模板，而是根据你最近表现给建议
- 不只关注增肌，也兼顾减脂期的力量保护和恢复管理

### 面向市场的表达
- 面向有训练基础用户的“训练进阶推荐器”
- 能读取真实训练记录并持续调整计划
- 像懂训练数据的私人教练，而不是固定课表工具

## 15. 开发优先级建议

## 第一阶段：可用 MVP
目标：完成“接训记数据 → 分析 → 生成下次训练建议”的闭环

优先级：
1. 账号与档案
2. 训记数据同步
3. 数据清洗与动作归类
4. 规则引擎
5. 今日训练推荐页
6. 基础解释文案

## 第二阶段：增强可用性
1. 趋势图表
2. 周期建议
3. 局部强化模式
4. 更细的恢复提醒
5. 手动修正动作分类

## 第三阶段：增强粘性
1. 用户反馈闭环
2. 推荐效果追踪
3. 更细的个性化模型
4. 多数据源接入

## 16. 建议的首版产品结论

如果现在进入开发，建议把产品首版定义为：

> 一个能连接训记、分析最近训练表现，并为有经验训练用户生成“下一次训练建议”的个性化推荐工具。

首版最重要的不是做大，而是做准：
- 数据接得稳
- 建议讲得清
- 进阶逻辑可信
- 用户愿意真的照着练一次

## 17. 当前需要你确认的关键决策

建议你优先确认以下 8 项：

1. **目标用户是否只做“有经验训练者”**
   - 建议：是，先不做新手

2. **首版是否只做“下次训练建议”**
   - 建议：是，把价值打透

3. **首版是否只接入训记，不做多平台**
   - 建议：是，先把一个数据源打通

4. **首版是否先以“规则引擎”为主**
   - 建议：是，先追求稳定和可解释

5. **是否支持三种核心目标模式**
   - 建议：增肌 / 减脂 / 力量提升

6. **首版是否支持局部强化目标**
   - 建议：可以支持，但先做轻量版

7. **是否要把饮食做深**
   - 建议：首版只做提醒，不做完整营养系统

8. **首版形态是 Web 还是 App**
   - 建议：优先 Web/H5 或轻量客户端，先验证逻辑
