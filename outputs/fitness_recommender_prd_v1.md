# 健身进阶推荐器 PRD v1.0

> 产品形态：首版 Web
> 
> 饮食模块定位：仅做提醒，不做完整营养系统
> 
> 数据来源：首版仅接入训记 API

---

# 1. 文档概述

## 1.1 产品名称（暂定）
健身进阶推荐器

## 1.2 产品愿景
帮助已有一定训练经验的用户，基于身体信息、训练习惯、恢复状态和训记训练记录，持续获得科学、可执行、可解释的训练进阶建议。

## 1.3 核心问题
目标用户普遍存在以下问题：
- 不知道自己当前状态是否适合加重量
- 不知道动作该如何循序渐进进阶
- 遇到平台期时，不知道该调整重量、次数还是训练量
- 减脂期不知道如何兼顾力量与肌肉维持
- 训练数据记录很多，但无法转成下一次真正可执行的计划

## 1.4 产品目标
构建一个能完成以下闭环的产品：
1. 读取训记训练记录
2. 分析用户当前训练状态
3. 给出下一次训练建议
4. 解释为什么这么建议
5. 随着新训练数据同步持续更新建议

# 2. 产品定位

## 2.1 产品定位
一个面向有训练经验用户的训练决策与进阶推荐工具。

## 2.2 非定位
本产品首版不是：
- 训练记录工具
- 新手入门教学工具
- 医疗康复建议工具
- 完整营养管理工具
- 社交健身社区

## 2.3 核心价值主张
- 告诉用户“下一次该怎么练”
- 基于真实训练记录动态更新建议
- 推荐结果可解释，而不是黑盒结论
- 同时兼顾增肌、减脂保肌、力量提升三类目标

---

# 3. 用户与场景

## 3.1 目标用户
- 训练经验 >= 6 个月
- 每周训练 >= 3 次
- 对组数、次数、重量有基础认知
- 有明确训练目标
- 已在使用训记做训练记录

## 3.2 核心使用场景

### 场景 1：训练前看建议
用户训练前打开产品，查看当天动作是否应加重、维持还是减量。

### 场景 2：平台期判断
用户发现某个动作停滞，查看系统是否判断为疲劳、训练量不合理或进阶策略问题。

### 场景 3：减脂期保强度
用户在减脂过程中查看主项是否应维持强度、辅助项是否该减量。

### 场景 4：周期管理
用户查看最近几周是否接近减量周，或者是否需要切换进阶方式。

# 5. 用户目标拆解

## 5.1 用户显性目标
- 卧推/深蹲/硬拉等主项稳定进步
- 增肌期提高训练质量与肌肉围度
- 减脂期尽量保住力量和肌肉
- 强化弱项部位

## 5.2 用户隐性目标
- 降低训练决策成本
- 避免盲目加重
- 获得更专业的训练反馈
- 形成长期正反馈

---

# 6. 核心流程

## 6.1 首次使用流程
1. 用户注册/登录
2. 填写基础档案
3. 设置训练目标
4. 设置训练分化与周频率
5. 填写恢复信息与饮食阶段
6. 输入训记 API Key
7. 拉取近 2-6 周训练记录
8. 生成首次分析与下一次训练建议

## 6.2 日常使用流程
1. 打开首页查看当前状态
2. 进入“今日建议”查看训练安排
3. 查看动作级加重/维持/减量建议
4. 训练结束后等待训记同步
5. 下次再次查看更新后的建议

# 7. 功能需求详述

# 7.1 账号与档案模块

## 7.1.1 功能目标
建立用户训练上下文，作为推荐引擎输入。

## 7.1.2 输入字段
### 基础信息
- 性别
- 年龄
- 身高
- 体重
- 体脂率（可选）
- 围度（可选）

### 训练背景
- 训练年限
- 每周训练频率
- 当前训练分化
- 主训练目标
- 强化部位（可选）

### 恢复与饮食
- 平均睡眠时长
- 压力等级
- 日常活动量
- 疼痛/旧伤情况
- 当前饮食阶段（增肌/维持/减脂）
- 饮食执行稳定度（高/中/低）
- 蛋白质摄入是否大致达标（是/否/不确定）

## 7.1.3 业务规则
- 基础信息首次必填
- 可随时更新，但更新后会影响推荐结果
- 若存在疼痛/旧伤，推荐策略自动保守

---

# 7.2 训记数据同步模块

## 7.2.1 功能目标
稳定接入用户训练数据，并支持持续更新。

## 7.2.2 用户操作
- 输入 API Key
- 点击“连接训记”
- 查看同步状态
- 手动重新同步

## 7.2.3 读取数据字段
优先读取：
- 训练日期
- 训练名称 / 训练日标签
- 动作名称
- 组序号
- 重量
- 次数
- RPE（若有）
- 备注（若有）
- 完成状态（若有）

## 7.2.4 同步规则
- 首次同步：读取最近 6-12 周训练数据
- 日常同步：增量更新
- 同步失败：提示失败原因
- API Key 无效：提醒重新填写

## 7.2.5 异常处理
- 动作名称异常：进入待映射列表
- 数据缺失：标注“不完整数据”
- 同一天重复记录：做去重处理

---

# 7.3 训练分析模块

## 7.3.1 功能目标
把训练记录转化为用户能理解的“状态判断”。

## 7.3.2 分析对象
- 单动作
- 单训练日
- 单肌群
- 用户整体训练状态

## 7.3.3 输出维度
### 动作层
- 最近表现趋势
- 是否达到进阶条件
- 是否处于停滞

### 训练日层
- 该训练日整体是否适合推进
- 是否存在疲劳偏高动作

### 整体层
- 当前状态类型
  - 正常推进
  - 保守推进
  - 维持
  - 减量
  - 平台调整
  - 减脂保护

### 目标层
- 当前安排是否符合用户目标
- 弱项部位训练量是否不足

---

# 7.4 今日训练建议模块

## 7.4.1 功能目标
输出最核心的用户价值：下一次训练该怎么练。

## 7.4.2 页面输出内容
### 顶部摘要
- 今日建议状态
- 本次训练建议类型（推进 / 保守 / 恢复）
- 关键提醒

### 动作卡片
每个动作展示：
- 动作名称
- 建议重量
- 建议组数
- 建议次数范围
- 建议状态（加重 / 维持 / 减量 / 替换）
- 简短原因说明

### 底部建议
- 本次训练节奏提醒
- 恢复与饮食提醒

## 7.4.3 业务要求
- 建议需覆盖主项与主要辅助项
- 主项解释必须展示
- 数据不足时必须标注可信度低

---

# 7.5 周期建议模块

## 7.5.1 功能目标
帮助用户理解未来 1-4 周训练方向。

## 7.5.2 输出内容
- 本周建议：继续推进 / 维持 / 临近减量周
- 下周期建议：是否切换策略
- 局部强化建议

## 7.5.3 首版要求
- 信息简洁
- 只输出关键结论
- 不做复杂长周期自动编程

---

# 7.6 饮食与恢复提醒模块

## 7.6.1 功能目标
提醒用户与训练结果强相关的饮食和恢复风险。

## 7.6.2 输出内容
- 睡眠不足提醒
- 压力过高提醒
- 当前减脂可能影响恢复提醒
- 蛋白质摄入可能不足提醒
- 体重下降过快风险提醒（若有数据）

## 7.6.3 产品边界
- 仅做提醒
- 不给食谱
- 不给热量精算方案

---

# 8. 非功能需求

## 8.1 可解释性
所有核心推荐必须带原因。

## 8.2 安全性
疼痛、恢复差、连续失败等情况下默认保守建议。

## 8.3 一致性
同类数据输入下，推荐输出应稳定，不应频繁跳变。

## 8.4 易用性
首次设置目标控制在 5 分钟内完成。

# 11. 风险与应对

## 11.1 数据风险
- 训记字段不稳定
- 动作命名不统一
- 记录不完整

应对：
- 动作映射表
- 待确认动作列表
- 数据可信度提示

## 11.2 推荐风险
- 建议过激进
- 建议不符合用户主观状态

应对：
- 首次推荐偏保守
- 疲劳与恢复优先级高于进阶冲刺

## 11.3 体验风险
- 首次配置太复杂
- 解释太专业难理解

应对：
- 先做必要字段
- 用通俗解释替代专业术语堆砌

# 13. 版本结论

首版要完成的不是“全能健身平台”，而是一个足够聚焦的训练决策助手：

> 接入训记数据，理解用户状态，并给出用户真正愿意执行的下一次训练建议。
